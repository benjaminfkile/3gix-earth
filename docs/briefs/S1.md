# S1: the shell

Repository: 3gix-shell, branch `grunt`. Contract: `/workspace/docs/design.md`. The MFE it loads is `/context/3gix-earth` (read its `docs/design.md` section 1 for the remote's name, module, and shared packages; it may not be built yet, so do not depend on its code).

## What to build

1. Vite + React 19 + TypeScript strict + MUI app, `package.json` scripts `dev`, `build`, `preview`, `test`, `typecheck`, and `ci` (typecheck, tests, build, then print `ci ok`). `.gitignore` covers `node_modules`, `dist`, `.env*`, `*.pem`.
2. `vite.config.ts`: the dev server per design section 3 (HTTPS only when both `GX_TLS_CERT` and `GX_TLS_KEY` are set, `GX_HOST`, `GX_SHELL_PORT` default 5180), and `@module-federation/vite` as host with the shared singletons of section 1. No remote is declared at build time.
3. `src/remote.ts`: works out the entry URL (design section 2 item 2) and loads `gx_earth/EarthApp` with the Module Federation runtime. Pure URL logic in its own function with tests (env set, env unset, http and https pages, a page on another hostname).
4. `src/App.tsx`: the loading, error with retry, and full page states of section 2. Tests with the loader mocked: shows progress, then the component; on failure shows the URL and error, and retry calls the loader again.
5. `README.md`: what the shell is, the environment variables, how to run it next to `3gix-earth`.

## Done when

- `npm run ci` prints `ci ok`.
- The summary gives the commit, the versions of Vite, React, MUI, and `@module-federation/vite`, and what you could not check without the MFE running.
